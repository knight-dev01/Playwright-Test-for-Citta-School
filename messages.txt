# 2. TESTING METHOD

For every workflow:

### Step 1 – Navigate

Open the relevant portal/module through the application's normal navigation.

### Step 2 – Identify

Identify:

* available controls
* forms
* buttons
* tables
* filters
* search
* validation messages
* permissions
* workflow states
* confirmation dialogs

### Step 3 – Execute

Perform the workflow using the authorised test account.

### Step 4 – Validate

Compare the observed behaviour with the expected behaviour in the evaluation document.

### Step 5 – Negative Testing

Where safe and appropriate, test:

* empty fields
* invalid values
* duplicate submissions
* invalid codes
* invalid IDs
* incorrect permissions
* boundary values
* repeated clicks
* direct URL access
* incomplete prerequisites
* incomplete payments
* incomplete approvals

Do not intentionally corrupt or destroy production data.

### Step 6 – Record Evidence

For every failure:

* take a screenshot
* record the URL
* record the exact error/message
* record the steps that produced it
* record the account/role used
* record the expected result
* record the actual result

# 3. AUTHENTICATION TESTING

Test every supplied user role.

Verify:

* valid credentials
* invalid username
* invalid password
* verification-code behaviour
* invalid verification code
* repeated verification failures
* lockout behaviour
* session creation
* logout
* session persistence
* session timeout if applicable

# 4. ROLE AND AUTHORISATION TESTING

Test access using:

* normal navigation
* direct URLs
* browser refresh
* copied URLs
* unauthorised modules

Attempt to access administrative functionality from a Student account.

Attempt to access Student functionality from an administrative account where inappropriate.

Record whether access is:

* Allowed correctly
* Denied correctly
* Incorrectly allowed
* Incorrectly denied

Treat unauthorised access to restricted functionality as a high-severity security defect.
